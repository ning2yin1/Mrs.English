# 画面レイアウト仕様

全座標は844×390 CSS pxの参考値。safe-areaは実端末で別に加算。静的配置図は1688×780pxで、本文をDOMで再描画する前提。写真領域は抽象グラデーションで仮置きし、人物は一切生成していない。

## 共通枠
上部ヘッダーx28/y16、主領域x28/y76〜320、ナビx20/y332/w804/h54。ナビの見えるアイコンが20pxでも、各タブのタップ領域は幅134×高54px。実機は安全領域を引いた残り幅を6等分する。
本文を安全領域に入れるため短辺が小さい端末では左右余白を再計算。ナビは56pxを基本にし、主領域側を可変にする。表示が不足したら一覧内部スクロールを使う。

## 詳細画面・重ね表示
以下は専用の全面モックアップを制作していない。個別部品と配置仕様は用意済み。

|表示|配置と使用素材|
|---|---|
|カード詳細|左180×252カード、右detail-panel内に名前/ランク/写真種別/獲得情報。右上close、左右next/back。カードが育成可能に見えるゲージは置かない|
|解説|scrim＋explanation-panel。上部に正誤と全文、下部に文法解説と音声。下部NEXT固定、本文のみスクロール|
|ログイン獲得|日枠の前にreward-claim、GPアイコンと獲得量。獲得後day-claimedへ切替|

|ロックチャット|locked-chat＋lock、必要な好感度をDOM表示。押すと条件を説明。未読のふりをしない|
|縦向き案内|濃紺背景、rotateアイコン、端末を横向きにする短い案内。ゲームの入力を背面で進めない|

## 写真の焦点
写真全体をcoverすると左右/上下が欠ける。背景ごとにfocalPoint{x,y}を0–1で記録し、object-positionへ変換する。人物が複数なら、顔全員が残るかを実写真で検査する。保証できない写真はcontain＋同写真由来のぼかし背景等の代替を検討する。今回の素材に人物の切り抜きや顔の修正は含まれない。

## 配置図の文字
環境依存の日本語フォント欠落を防ぐため、静的な正確配置図は英語で位置を説明している。アプリの実テキストを英語へ変更する指示ではない。PLAYの実例は「彼は歌手です。」→「He is a singer.」。生成コンセプトでは日本語の雰囲気も確認できるが、教材の正本には使わない。
